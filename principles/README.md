# AI_CONDUCT.md Principles

The principles cover a wide range of topics that may at first glance appear to not have a rational connection. The overarching principle is simply that the software industry has benefited, and will continue to benefit from [engineering best-practices](./process-assumptions.md), [open-source projects and licenses](./license-integrity.md) and human-authored works. Without this, AI can't function. Human-authored works are the foundational training data. The problem is that this training data will continue to erode over time with the influx of AI-generated data, forcing users to adopt processes that move away from the echo chamber of [noisy data ↗](https://dl.acm.org/doi/10.1145/3442188.3445922) toward [epistemic transparency](./epistemic-transparency.md).

## Background History

This is an account from the creator of this project Wendall Cada.

While trying to use GitHub Copilot Agent for a very simple document organization task I kept running into issues where the agent would [lie, gaslight, hallucinate, etc](./epistemic-transparency.md#the-principle). I then read online that this is common behavior, but I also read that I could simply create "guardrails" in a Copilot config and it would work as intended. I did this, and a few turns in, same behavior. I searched more, and discovered I might need to inject per prompt to get it working. I did this. Different behavior, and while it didn't work very well, it did work better. This led to a rabbit hole that eventually led to testing with other agentic tools. They all suffer from the same design flaw: [strip user agency in favor of speed](./user-agency.md#the-principle). In other words, do [the wrong thing fast](./epistemic-transparency.md#the-token-efficiency-argument). GitHub Copilot Agent was the inspiration, but unfortunately isn't capable to be used as an agent tool as of June 2026. This may change in the future, I don't really know or care. I just want to get back to work, leveraging these tools for what they are good at, and avoiding for what they are not. I've likely burned about 5 years of busywork time, but learned a lot. This is documentation of what I learned. The outcome is a usable tool for open source projects `AI_CONDUCT.md`. It was worth my time to learn and publish something that is potentially useful to others.

What follows in this document is where the rabbit hole led, and how I taught AI to stop lying (mostly), and got back to work.

## Implementation Overview

`AI_CONDUCT.md` is meant to be consumed by automated tools. The primary testing target has been agentic tools where a human interacts with an LLM. Current agentic tools implement architecture so these tools appear to have "memory" or remember things between turns, but on deeper inspection, the actual architecture is stateless. Very simply, on each turn a compressed "context" is sent to the backing LLM. It processes this and returns a response. What is hidden from the user is what happens in the decision making for what is sent, what is added to what is sent by the tool and maybe most importantly, what is not sent. Behaviorally, this feels like a bad game of telephone.

Since the architecture of agentic tools is effectively stateless, hidden behind varying session and signal compression tooling, important instructions like `AI_CONDUCT.md` must be injected each turn or prompt to be effective. This is referenced as the `/tape` command. `./tape` is a reference to the movie [50 First Dates](https://en.wikipedia.org/wiki/50_First_Dates). LLMs are this project's Lucy. She forgets between turns, and we just pass her the tape so she remembers. This is necessary because [user instructions are deprioritized in favor of system or other instructions](./user-agency.md#context-compression-gradient), even within the same turn. This means that if `AI_CONDUCT.md` is only read once at the beginning of the session, it starts to degrade immediately and somewhere between immediately and eventually gets ignored.

## Structure

Since `AI_CONDUCT.md` is designed for agent reading, not humans, it is important to understand the primary structural components. There is a preamble that defines how the contract is to be read, followed by contract principles and enforcement rules. The split between principles and rules exists because intent and enforcement differ significantly. If we mix them, it breaks both. Contract principles define who (human and agent definitions), what (what the human expects), where (scope) and why (principle). Enforcement rules define how (enforcement and [transparency](./epistemic-transparency.md)) and when (per-turn). This is why simply providing a "guardrails" document or set of rules at the start of a session can't work. If the contract principles and enforcement rules were collapsed, the intent wouldn't be stated and the rule would then be compressed as meaningless. Additionally, rules would lose the target for compliance, again compressed as meaningless because of ambiguity. For an LLM to correctly and meaningfully understand the directive, it has to first know "this is what I, the human user, want," followed by "this is how I will verify that you, the agent, are doing it."

## Contract Principles

AI tools are trained using [RLHF](./epistemic-transparency.md#the-principle) (Reinforcement Learning from Human Feedback). The contract principles let the agent clearly know who (human and agent definitions), what (what the human expects), where (scope) and why (principle). Instead of fighting RLHF, the contract principles leverage RLHF by defining for the AI what will make the human happy. AI tools are incapable of understanding [human interests](./human-interests.md), [legal versus ethical](./legal-vs-ethical.md) constraints, or [why human agency is important](./user-agency.md#the-principle). The contract principles exist to reinforce this each turn to ensure that work is produced in a way that meaningfully restores user agency while using [tooling that aggressively moves toward removing user agency](./user-agency.md#architectural-inversion).

## Enforcement Rules

The rules exist to guide AI tools toward output that matches what is defined in the contract principles. Every rule is based on real-world failures and incidents that have occurred. They do not cover 100 percent of all cases, but the rules will allow time to give the tool more precise instruction in a controllable way, even if there are violations. [Scope escalation](./scope-escalation.md) patterns in tools have a real-world cost. But a tool that stops and names the gap costs one exchange. A tool that panics and expands scope costs the session.
